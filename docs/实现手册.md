# 桌面系统实现手册（复现版）

> 这份文档只讲「怎么实现出来的」：架构、数据流、每个组件的职责、接口协议、以及踩过的坑。
> 想学怎么用，看《桌面系统使用手册.md》；想照着在自己的电脑上复刻一套，看本文。

---

## 1. 两套系统与进程拓扑

这套桌面由**两个互相独立的系统**组成，靠本机 HTTP 通信，不共享进程、不共享内存：

```
┌───────────────────────────── Windows 桌面 ─────────────────────────────┐
│                                                                        │
│  Lively Wallpaper (WebView2)          DesktopPage.ahk (AutoHotkey v2)  │
│  └─ <壁纸目录>/index.html              └─ 抽屉窗口（全屏、盖在壁纸上） │
│     ├─ app.js  上游模拟器主逻辑           ├─ 图标页 / 图标池 / 拖拽      │
│     ├─ hw.js   本机硬件面板               ├─ 文件夹 / 右键菜单           │
│     ├─ wx.js   天气面板                   └─ 顶部快捷栏 / 托盘           │
│     ├─ todo.js 待办面板                                                │
│     ├─ media.js 当前播放                                               │
│     └─ dsh.js  DSH 控制台桥接                                          │
│              │                                  │                       │
│              │  JSONP / 1x1 GIF 信标            │  读写文件             │
│              ▼                                  ▼                       │
│        dsh-agent.ps1（PowerShell 5.1，监听 127.0.0.1:17433）            │
│         ├─ /state.js /media.js /dock.js   拉数据（JS 赋值）             │
│         ├─ /run.gif /launch.gif /media.gif 触发动作（信标）              │
│         ├─ /rect.gif /scroll.gif          接收壁纸上报的几何与滚轮      │
│         └─ 读写 todo.txt / dock.txt / panel-rect.txt / scroll.dat      │
│                                   ▲                                     │
│                                   │ 读 panel-rect.txt / 写 scroll.dat   │
│                            DesktopPage.ahk 的滚轮分流                    │
└────────────────────────────────────────────────────────────────────────┘
```

要点：

1. **壁纸页面是 `file://` 打开的**，不能 `fetch` 本机端口（Chrome/Edge 对 file:// 的私有网络访问有限制），所以全部改用两种老办法：
   - **JSONP**：动态插 `<script src="http://127.0.0.1:17433/xxx.js?v=时间戳">`，服务端返回 `window.__XXX = {...}`；
   - **1×1 GIF 信标**：`new Image().src = '.../xxx.gif?op=...'`，服务端动作执行完回一张透明 GIF。
2. **抽屉是独立的 AutoHotkey 进程**，全屏无边框窗口，盖在壁纸上方；壁纸里的按钮点击不到它，它也不碰页面 DOM。
3. **两边唯一的耦合是三个文件**：`panel-rect.txt`（壁纸告诉抽屉「DSH 控制台在屏幕哪儿」）、`scroll.dat`（抽屉告诉壁纸「滚了几格」）、`todo.txt`（待办真源，代理生成 `todo-data.js` 给壁纸读）。

## 2. 目录约定

| 路径 | 内容 |
|---|---|
| `%LOCALAPPDATA%\Lively Wallpaper\Library\wallpapers\<壁纸目录>\` | 壁纸本体（index.html + 各 JS/CSS + 生成的 `*-data.js`）。目录名有两种叫法：现场这份是 Lively 早期分配的 `dsqq0001.ab1`，`install.ps1` 默认装成 `大肥鱼桌面系统` —— 所以代码里**不许写死目录名**，统一按 `DSH_WALLPAPER` → `WallpaperLayout.json` 的 `LivelyInfoPath`（当前应用的）→ 「库里含 dsh.js 的最新一份」→ 兜底 的顺序解析 |
| `%LOCALAPPDATA%\DesktopPage\` | 抽屉：`DesktopPage.ahk`、`dsh-agent.ps1`、`AutoHotkey64.exe`、`npix.exe`、数据与日志、`icons\` |
| `%LOCALAPPDATA%\DesktopPage\start-all.vbs` | 开机启动器（藏窗口拉起三个进程） |
| `%LOCALAPPDATA%\DesktopPage\ensure-all.vbs` | 兜底巡检（计划任务 `DesktopPage Ensure` 每 2 分钟跑一次） |
| `%LOCALAPPDATA%\DesktopPage\dock.txt` / `todo.txt` | 快捷启动 / 待办 的真源文本 |
| `E:\DSH`（可配） | DSH 本体，用于「给 DSH 发指令」「启动/打开网页」 |

三个进程都由 **Windows 计划任务 `DesktopPage Autostart`** 启动，任务动作是 `wscript.exe start-all.vbs`，以当前用户身份、最高权限运行。**必须走计划任务**：直接双击 `Lively.exe` 会丢失 WebView2 的 DPI 感知，整屏放大 1.5 倍。

另有第二个任务 **`DesktopPage Ensure`**（`wscript.exe ensure-all.vbs`，每 2 分钟）：只补缺失的抽屉/看门狗/代理，并消费 `launch-queue.txt`。两个任务都由 `install.ps1` 创建、`uninstall.ps1` 删除。

> 全量接口表、文件职责、数据文件格式、排障工具与「改完要同步哪些文档」，见 **`docs\项目地图.md`**（本手册偏"为什么这样做"，项目地图偏"现在是什么样"）。

## 3. 桌面系统（壁纸）

### 3.1 文件与职责

| 文件 | 行数级别 | 职责 |
|---|---|---|
| `index.html` | 300+ | 骨架：左栏信息、右栏面板、顶部 TODO 条、底部时钟、设置抽屉 |
| `app.js` | 83KB 压缩 | **上游原作者代码，不要改**：立绘动画、情绪、天气渲染骨架、设置持久化 |
| `style.css` | 34KB | 上游样式 + 我们自己追加的 `#dshPanel` 等少量规则 |
| `layout.css` | 10KB | 布局：`.left-panel` / `.right-panel` / `.bottom` 定位 |
| `todo.css` | 13KB | 我们新增面板的样式（TODO、硬件、天气、DSH、当前播放） |
| `dsh.js` | 400+ | DSH 控制台 + 设置面板桥接 + 几何上报 + 滚轮 |
| `hw.js` / `wx.js` | 60 / 100 | 轮询 `hw-data.js` / `wx-data.js` 并写进面板 |
| `todo.js` | 170 | 待办 CRUD（本地缓存 + 每 3 秒比对 `todo-data.js` 的 mtime） |
| `media.js` | 130 | 当前播放：轮询 `/media.js`、按钮发信标、面板高度自适应 |
| `hw-data.js` / `wx-data.js` / `todo-data.js` | 生成物 | 代理写出的 `window.__HW=…` 等快照 |

### 3.2 面板是靠「替换上游节点」实现的

上游 `app.js` 按 id 找元素，所以**不能删节点，只能替换内容或隐藏**：

- `#consolePanel`（上游的 DEEPSEEK/RUNTIME 控制台）：`dsh.js` 启动时 `style.display='none'`，紧接着插入自己的 `#dshPanel`；
- `#systemInfo` / `#weatherInfo`：保留结构，由 `hw.js` / `wx.js` 覆写内部文本；
- `#musicPanel`：上游音乐面板，全程 `hidden`，**必须保留**（`app.js` 里 `new It(a("musicPanel"))`，删了直接抛错）；
- `#topResources` / `#layoutStatus` / `#taskbarStatus`：`app.js` 直接写 `textContent`，保留即可。

### 3.3 dsh.js 的三条通道

```js
// ① 拉状态：1.2 秒一次，单飞 + 序号校验
stateBusy / stateSeq: 只接受最新一次请求的响应；2.5 秒超时强制解锁
GET /state.js  → window.__DSH_STATE = {web, scroll, busy, bal, drawer, lines:[...]}

// ② 触发动作：信标，不等结果
new Image().src = '/run.gif?t=' + encodeURIComponent(text)
              → /launch.gif、/open.gif、/clear.gif、/drawer.gif、/media.gif?op=…

// ③ 几何上报：把控制台矩形换算成万分比传给抽屉
GET /rect.gif?x=&y=&w=&h=   // 0..10000 的比例，不是像素
```

设置面板打开时，`/rect.gif` 上报**整屏** `0,0,10000,10000`——这样抽屉的滚轮判定会把「面板区域」当成控制台区域，走滚动而不是呼出抽屉。

### 3.4 当前播放（media.js）

- 数据源优先级：**Windows 媒体会话（GSMTC）** → **网易云兜底**（网易云 3.1.x 不发布 SMTC 会话）；
- 兜底三要素：窗口标题取「歌名 - 歌手」、WASAPI 音频会话峰值判在播（暂停时峰值恒 0）、`playingList` 里取时长；
- 进度本地估算，时间前带 `≈`；面板高度由 `fit()` 撑到下方时钟分界线上沿；
- 三个按钮 → `/media.gif?op=back|toggle|fwd` → 代理发**系统媒体键**（上一首 0xB1 / 播放暂停 0xB3 / 下一首 0xB0），不打开播放器窗口、不抢前台。

## 4. 抽屉系统

### 4.1 结构（DesktopPage.ahk，约 2100 行）

```
#Requires AutoHotkey v2.0 / #SingleInstance Force / #Warn LocalSameAsGlobal, OutputDebug
   ↓
全局配置区（APP_DIR、GUI_W/H、网格尺寸、数据文件路径、ONESHOT、NO_ACRYLIC…）
   ↓
数据层：LoadItems / LoadPositions / LoadHidden / SaveLayout / SaveHidden
   ↓
窗口层：CreateDrawer（全屏 GUI + 顶部栏 + 标题 + 页码 + 图标池）
        ShowDrawer / HideDrawer / FadeIn / FadeOut（WS_EX_LAYERED 改 alpha，每步 <2ms）
        EnsureOverlay（毛玻璃/亚克力备选）
   ↓
渲染层：UpdatePage（按页刷新图标池）/ PlaceItem / ResolveOverlaps / RenderFolders
   ↓
交互层：$WheelDown / $WheelUp / Esc / ^!Space / ^!d、拖拽 DRAG、右键菜单、重命名框
   ↓
入口：StartupArgs()（--selftest / --diag / --scrolltest / --tiptest / --plain / --page=N …）
```

关键实现点：

- **图标池**：不复用系统桌面图标，而是自己用 `Picture + Text` 控件画；滚动到下一页时复用同一批控件（`CTRL_POOL`），避免频繁销毁重建；
- **两页模型**：`curPage=0` 是干净桌面（窗口隐藏，系统图标被隐藏），`curPage>=1` 是图标页；
- **拖拽吸附**：拖动结束时按 `CELL_W/CELL_H` 取整落点，与已有图标坐标做重叠消解（`ResolveOverlaps`）；
- **文件夹**：两个图标叠在一起就合并，数据存在 `layout.dat` 的 `F` 行，成员用 `|` 分隔；
- **系统图标隐藏**：`Ctrl+Alt+D` 切 `SHELLDLL_DefView` 的可见性；程序退出时必须还原（`ExitCleanup`，`ONESHOT` 模式跳过还原以免自检把图标放出来）。

### 4.2 数据文件格式

```
items.tsv        一行一个桌面项：<类型>\t<路径>\t<名称>
desktop_positions.tsv  真实桌面图标坐标：<路径>\t<x>\t<y>（供「还原位置」用）
layout.dat       V2 头 + P\t<路径>\t<x>\t<y> + F\t<id>\t<名称>\t<x>\t<y>\t<成员1|成员2>
hidden.dat       一行一个被隐藏的项
dock.txt         一行一个快捷启动：<名称>\t<目标路径>[\t<参数>]
todo.txt         一行一个待办：<完成:0/1>\t<文本>
```

**写文件一律「临时文件 + 原子替换」**（`FileAppend(tmp)` → `FileMove(tmp, 目标, 1)`），不要先 `FileDelete` 再写，否则进程被杀就丢布局。

### 4.3 滚轮分流（两系统唯一的实时耦合）

```
鼠标滚轮
  ↓ AHK 热键 $WheelDown
抽屉正开着？ ──是──▶ 翻页（图标页）
  │否
光标在「控制台区域」内？（读 panel-rect.txt，±12px 容差）
  ├─ 是 ──▶ 写 scroll.dat（一行一个 +1）──▶ 代理 /scroll.js 读走 ──▶ 页面滚日志/滚设置面板
  └─ 否
     光标在桌面/壁纸空白？ ──是──▶ 呼出抽屉
                          └─ 否 ──▶ 把滚轮原样发给前台窗口
```

`panel-rect.txt` 的格式是 `x y w h`，值是 **0..10000 的万分比**（跨 DPI 安全），AHK 侧按当前屏幕尺寸换算。

### 4.4 dsh-agent.ps1 路由表

| 路由 | 作用 |
|---|---|
| `/state.js` `/state` | DSH 状态（web/busy/余额/日志尾巴） |
| `/media.js` | 当前播放（GSMTC 优先、网易云兜底，带 `est` 标记） |
| `/media.gif?op=toggle\|back\|fwd` | 发系统媒体键（0xB3 / 0xB1 / 0xB0） |
| `/dock.js` `/dock.gif?op=del&i=` `/adddock.gif` `/launchpath.gif?t=` | 快捷启动列表与增删、启动文件 |
| `/todo.gif?op=…&t=` | 待办增删改，写 `todo.txt` 并生成 `todo-data.js` |
| `/run.gif?t=` `/launch.gif` `/open.gif` `/clear.gif` `/drawer.gif` | DSH 指令 / 打开网页 / 清屏 / 呼出抽屉 |
| `/rect.gif?x&y&w&h` | 壁纸上报矩形（万分比）→ `panel-rect.txt` |
| `/scroll.gif?d=±1` `/scroll.js` | 滚轮增量：追加 `scroll.dat` / 取走并清零 |
| `/summon.gif?d=1\|hide` | 写 `summon.cmd` 召唤/收起抽屉——**不依赖任何键鼠钩子**的第三条通道 |
| `/icon/<file>` | 供页面加载抽屉图标缓存 |

约定：`*.js` 返回 `window.__XXX=…`，`*.gif` 一律返回 1×1 透明 GIF（`Write-Raw` 直接写字节，别用 `Write-Js`），并且**先回包再执行动作**。

## 5. 踩过的坑（按坑法分类）

### 5.1 编码与 BOM

1. **PowerShell 5.1 按 ANSI 读 `.ps1`**：脚本里只要有中文正则/字符串，无 BOM 就会读成 GBK 乱码，报「正则表达式模式 … 无效」。→ 所有 `.ps1` 存 **UTF-8 with BOM**。
2. **AHK 侧写 TSV 不要用 `"UTF-8"` 编码**：`FileAppend` 首次写入会带 BOM，代理读到的第一行是 `\uFEFF1`。→ 用 `"UTF-8-RAW"`。
3. 用 PowerShell here-string 拼文档时，双引号字符串里的反引号是转义符（`` `t ``=TAB、`` `0 ``=NUL），会往文档里塞控制字符。→ 用**单引号 here-string**。

### 5.2 窗口、DPI 与像素

4. **DPI 虚拟化**：PowerShell/AHK 进程未声明 DPI 感知时，`GetWindowRect` 拿到的是「虚拟化坐标」（150% 缩放时只有真实尺寸的 2/3），`CopyFromScreen` 截出来的图和坐标对不上。→ 在进程内设 `SetProcessDpiAwarenessContext(-4)`（PMv2），或用带 manifest 的独立小工具（本项目是 `npix.exe`）。
5. **`Get-Process <exe>.MainWindowHandle` 不可靠**：网易云会把主窗口指向一个 8×8 的 `Chrome_WidgetWin_0`。→ 按窗口类名 + 面积自己挑（`NEMain()`）。
6. **不要用 `GetPixel` 全屏逐像素扫**：5 万次调用能跑 90 秒。→ 先 `Graphics.CopyFromScreen` 抓成 Bitmap，再在内存里扫。

### 5.3 媒体与音频

7. **WASAPI 会话 state 在暂停后仍可能是 1**，不能用它判在播。→ 用 `IAudioMeterInformation.GetPeakValue` 采样：暂停恒 0.0000，播放 0.15–0.4。
8. **网易云暂停有 1–2 秒淡出**：点完立刻测峰值会读到大数字，误判「没生效」再点一次，结果把自己点回播放。→ 复核要等 1.6 秒以上，且只在「预期暂停」方向复查。
9. **网易云 3.1.37 不注册 GSMTC 会话**（渲染进程命令行里带 `--disable-features=MediaSessionService,…`），所以只能在媒体键 / 窗口标题 / 音频峰值上做兜底。
10. **合成鼠标点击落不到壁纸层**：`mouse_event` 在壁纸区域会被桌面图标层接走。→ 壁纸端按钮只能验证到 HTTP 层，真机点击靠用户手点。

### 5.4 file:// 与页面

11. **file:// 下 `fetch` 本机端口会被拦**：一律退到 JSONP + GIF 信标。
12. **file:// 下的跨源脚本报错会被脱敏成 `Script error.`**：`window.onerror` 拿不到详情，只能靠同源 http 复现（`node` 起个静态服务器即可）。
13. **`dsh.js` 里 `reportRect` 有去重**：页面一旦缓存了 `lastRect`，外部把 `panel-rect.txt` 改坏后页面永不重发。→ 定时器改成「强制上报」。
14. **`MediaQueryList` 式的初始化无 try/catch**：任一元素 id 改了就永远停在「连接中」。→ 整个 `dshInit()` 包 try/catch，并把错误写进 `document.title` 便于排查。

### 5.5 AHK 特有

15. **函数里写 `X := …` 而没声明 `global X`**，会悄悄创建局部变量，看起来「改了但没生效」：`FORCE_DIRTY`、`NO_ACRYLIC`、`LAST_HOVER` 都栽过。→ 函数头显式 `global`，并开 `#Warn LocalSameAsGlobal`（用 `OutputDebug` 级别，别让它弹窗中断加载）。
16. **裸 `global` 是陷阱**：`FadeIn/FadeOut` 里一句裸 `global` 会把 `t`、`e`、`steps` 全变成全局，还会和别处的 `catch as e` 撞名。→ 删掉裸 `global`，变量改名。
17. **`Esc::` 是全系统热键**：抽屉没开时也吞掉 Esc，别的对话框就收不到。→ 先判 `IsWindowVisible`，不属于自己就 `return` 放行。
18. **自检/调试入口忘记设 `ONESHOT`**：`ExitApp` 时走清理逻辑，会把系统桌面图标放出来。→ 所有一次性入口统一 `ONESHOT := true`。

### 5.6 启动与权限

19. **直接启动 `Lively.exe` 会丢 DPI 感知**，整屏被放大。→ 统一走计划任务 + `start-all.vbs`。
20. **杀代理进程时别用「命令行包含 dsh-agent.ps1」做过滤**：会命中当前这条 pwsh 命令本身，把自己杀掉（退出码 4294967295）。→ `Where-Object { $_.ProcessId -ne $PID -and $_.CommandLine -like '*-File*dsh-agent.ps1*' }`。

## 6. 从零复现（10 步）

1. 装 **Lively Wallpaper**（WebView2 版）+ **AutoHotkey v2**，把壁纸文件放进 Lively 库的任意目录（目录名随意，代码会自动发现），Lively 里指向 `index.html`。
2. 在 `%LOCALAPPDATA%\DesktopPage` 放 `DesktopPage.ahk`、`dsh-agent.ps1`、`AutoHotkey64.exe`、`start-all.vbs`，图标缓存与数据文件目录建好。
3. 编译/放置 `npix.exe`（DPI 感知的截图+点击小工具，`csc /win32manifest npix.manifest npix.cs`）。
4. 建计划任务 `DesktopPage Autostart`：动作 `wscript.exe start-all.vbs`，最高权限、登录时触发。
5. 启动后确认：17433 端口能 `curl /state.js`、`/media.js`；Lively 页面出现 DSH 面板。
6. 改 `index.html`：删掉上游 `#consolePanel` 内容前先确认 `dsh.js` 会隐藏它；加入 `#dshPanel`、`#mediaPanel`、`#todoPanel` 的骨架。
7. 写 `dsh.js`：三条通道（拉状态 / 发信标 / 上报矩形），设置面板打开时把矩形上报成整屏。

## 9. 2026-11-03 修复记录：空终端窗、启动延迟、滚轮失灵

三个症状、三条互不相同的链：

### 9.1 空「管理员:」终端窗 = 控制台创建方式，不是提权

- 本机 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\EnableLUA = 0`（UAC 关闭），explorer.exe 本身就是 elevated，所以整条链**本来就都是管理员**；「以普通权限重启」在这台机器上无法实现，用计划任务（RunLevel=Limited）重启实测照样提权。

### 9.9 现场快照命令 `summon.cmd = diag`（2026-11-03 21:31 补）

用户不用翻日志，也不用我在他机器上敲命令：往 `summon.cmd` 写一个 `diag`，抽屉 400ms 内的计时器会落一行自带上下文的日志，例如

字段含义：`page` 当前页（0=收起）· `vis` 图标层是否可见 · `desk` 光标下方是否判为桌面 · `cls/proc/at` 命中的窗口类/进程/坐标 · `raw_ok` = Raw Input 注册结果（1 成功）· `raw_alive`/`hk_alive` = 两条滚轮通道是否发生过事件（本进程生命周期内首次命中才置 true）· `raw_ticks` = 收到的真实鼠标 Raw Input 条数 · `wheel_hits/last_dir/last_src` = 决策层被调用次数与最近一次方向/来源（`hk` 热键 / `raw` Raw Input / `key` 键盘兜底 / `selftest` 自检）· `hk_age/raw_age` = 距上次滚轮事件多久（毫秒）。

排障顺序：先 `diag` 看 `desk` 对不对（不对＝判定层问题）；再真滚一下，`wheel_hits` 涨了说明通道通、`last_src` 告诉你是哪条；`wheel_hits` 不涨而 `raw_ticks` 涨说明只有 Raw Input 通（钩子又掉了）；两者都不涨说明事件根本没到进程。


字段：`hwnd` 就是你给的那个窗口 · `cls/proc/vis` = 它的类名/进程/是否可见 · `root/root_cls/root_proc` = `GetAncestor(hwnd, GA_ROOT)` 得到的**顶层窗口**及其类名/进程 · `desk` = `ClassifyDeskWindow()` 的最终结论（1=当桌面/壁纸，0=不当）· `page` = 当时抽屉页（>0 时抽屉自身窗口一律算桌面）。

### 9.10 判定层的两个边角（2026-11-03 21:28 补）

- **越界坐标不能当桌面**：`MouseGetPos` 偶尔返回 `at=2420,-421` 这种越界值，`WindowFromPoint` 取不到窗口 → 旧代码 `if !h return true` 会判成"在桌面"，表现为在浏览器里滚轮也误召唤抽屉。现在 `DesktopUnderCursor()` 先过 `PointOnVirtualDesktop()`（`GetSystemMetrics` 的 76/77/78/79 = 虚拟桌面矩形），越界直接 `return false`；`HoverProbe()` 也跳过越界读数，不再往日志里写垃圾坐标。
- **抽屉的三个窗口都算"自己"**：抽屉开着时命中 `DPOverlay`（覆盖全屏的透明事件层）以前会被判成"非桌面"（`hover: desk=0 cls=AutoHotkeyGUI`）。`ClassifyDeskWindow()` 现在 `curPage>0` 时同时认 `gDrawer` 与 `gOverlay`。功能上滚轮上滑收起走的是 `curPage=1 → HideDrawer()`，不经过判定；但日志必须说实话，否则以后排障会被误导。
- 实测：开抽屉 → `hover: desk=1 cls=AutoHotkeyGUI proc=AutoHotkey64.exe`；关抽屉 → `hover: desk=0 cls=Chrome_RenderWidgetHostHWND proc=msedge.exe`。
- **判定必须锚定顶层窗口**：内层类名（`SHELLDLL_DefView` / `SysListView32` / `SysHeader32`）在系统进程里到处都有同名兄弟，只看内层等于"只要父链里出现过这个名字就当桌面"。2026-11-05 的「资源管理器里下滑滚轮召唤抽屉」就是这个洞，详见 §12。



### 9.11 Raw Input 兜底通道曾经是死代码（2026-11-03 21:33 修）

- 症状表征：`wheel.log` 里 `rawinput: register=1`（注册"成功"），但 `raw_ticks` 永远是 0，`wheel channel alive: raw` 从没出现过——`OnRawWheel` 一次都没被调用。
- 根因：`RegisterRawInputDevices` 的 `hwndTarget` 填的是 `gDrawer.Hwnd`（Gui 窗口），而 `OnMessage(0x00FF, OnRawWheel)` **只监视脚本主窗口（`A_ScriptHwnd`）收到的消息**。WM_INPUT 全进了 Gui 的窗口过程，回调根本不该被期望触发。
- 修法：`NumPut("Ptr", A_ScriptHwnd, rid, 8)`，日志改成 `rawinput: register=<1/0> target=<hwnd>`；另外加 `RAW_MSGS` 计数（在 `OnRawWheel` 第一行自增，出现在 `diag:` 里），用它做"接线测试"：向主窗口 `PostMessage(0x00FF)` 三次 → `raw_msgs=3`，证明消息真能进回调（假消息 `lParam=0` 会被 `GetRawInputData` 判长度不足后 return，不影响行为）。
- 开销实测：修好后抽屉空闲 15 秒 CPU 时间 31ms（≈0.2% 单核），`raw_msgs` 不因鼠标移动而暴涨到影响手感（真实设备每秒几百条 WM_INPUT，处理函数只做两次 `GetRawInputData` 与几个 `NumGet`）。
- 意义：这是"钩子被系统摘掉"时的兜底。之前兜底等于不存在，所以钩子一掉滚轮就彻底哑；现在即使钩子死，Raw Input 仍能把滚轮事件送进 `WheelHandle(…, "raw", …)`（`last_src=raw` 可辨）。
### 9.13 代理"空闲假死"：心跳只在有请求时前进（2026-11-03 21:40 修）

- 症状：`agent-watch.log` 每 50 秒一轮 `watch: agent unhealthy #2 pid=… alive=True hb=False port=True` → `kill` → `restart`；用户侧就是"点应用卡住 / 提示启动失败已排队"，而且看起来代理"总在重启"。
- 探针判定：连续采样 `dsh-agent.hb` 的 mtime —— 空闲 6 秒后 `age=27.6s`（内容不变），紧接着打一次 `/var` 立刻 `age=0.4s`。→ **心跳只跟着请求前进**。
- 根因：`while ($listener.IsListening)` 循环顶部写心跳，但循环体里 `$ctx = $listener.GetContext()` 是**阻塞调用**，没有请求就一直卡在里面，循环根本不转 → 心跳停 → 45 秒后被看门狗判死。
- 修法（`dsh-agent.ps1` 主循环）：改成带超时的异步等待，等待期间持续刷心跳——
  `$tWait = $listener.GetContextAsync()`；`while (-not $tWait.AsyncWaitHandle.WaitOne(250)) { if (-not $listener.IsListening) { break }; [IO.File]::WriteAllText($hbFile, ...) }`；`$ctx = $tWait.GetAwaiter().GetResult()`。
- 验证：重启代理后空闲采样三次 `age=0.1/0.1/0.2s`（每 4 秒一跳）；连续 100 秒无 `unhealthy` 记录、pid 不变（26356）、`/var` 200；端到端启动 `hb-test.txt` → `launchpath via explorer: … (57ms)` / `req done 78ms`，客户端 53ms。
### 9.14 「启动失败，已排入队列」这条兜底到底有没有用（实测）

- 复核方法：`taskkill` 掉代理 → 立刻用 `--launch=<文件>` 起一个抽屉实例（等价于点那个文件）→ 读三处日志。
- 实测（21:25）：抽屉 `launch agent unavailable: (0x80072EFD)`（连不上，毫秒级返回）→ `launch queued (agent down): …\q.txt`；看门狗 `21:25:41 watch: queued launch …\q.txt` → notepad 16412 于同一秒起来；`21:25:43 watch: restart ok pid=15756` 代理恢复。**排队到真正打开约 5 秒**，文件确实打开，队列文件被消费掉。
- 改前的两个丢弃阈值（watch 20 秒 / ensure 180 秒）是"点了永远没打开"的来源：代理重启 + 队列扫描都慢，超过阈值的条目被静默删掉；现在 5 秒扫描 + 300/600 秒阈值，兜底才成立。

### 9.15 冷启动实测（2026-11-03 21:43，等同于"重启电脑后"）

- 方法：`taskkill` 掉抽屉/代理/看门狗（含所有 AutoHotkey64 残留）→ 确认 `ahk=0` → `Start-ScheduledTask '\DesktopPage Autostart'` → 每 0.7 秒轮询"三个 pid 有效 + 17433 可连"。

### 9.16 编码陷阱：PowerShell 5.1 读"UTF-8 无 BOM"的中文会乱码甚至解析失败

- 本机脚本宿主是 **Windows PowerShell 5.1**（`$PSVersionTable` = 5.1.26100.9711）。它读 `.ps1` 时：**有 BOM 按 UTF-8，无 BOM 按 ANSI(GBK)**。
- 实测对照（同一个文件内容，只差 BOM）：无 BOM 时 5.1 把 `启动失败：已排入启动队列` 读成 `鍚姩澶辫触锛氬凡鎺掑叆鍚姩闃熷垪`（码点 935A E21A 59E9 …）；有 BOM 时读回正确（542F 52A8 5931 8D25 …）。更严重的情况：中文落在字符串里会让 5.1 报 `The string is missing the terminator: "."` 直接解析失败（本机复现过）。
- 处置：`dsh-agent.ps1` / `ensure-all.ps1` / `agent-watch.ps1` 三份脚本已统一改存 **UTF-8 with BOM**（各 +3 字节，`Parser::ParseFile` 0 错误，`verify.ps1` 只做存在性检查不受影响）。`verify.ps1` 本来就是 BOM，`start-all.vbs` 是 UTF-16LE，`DesktopPage.ahk` 由 AHK v2 按 UTF-8 读、无需 BOM。
- 排查口诀：`Get-Content` 在 5.1 里默认按 ANSI 解码，看到的"乱码"先别急着改文件 —— 先用 `[Text.UTF8Encoding($false,$true)].GetString(bytes)` 严格解码判定文件本身是否合法 UTF-8；要判定"运行时会不会乱"，看**执行脚本的那个宿主**而不是当前 shell。

### 9.17 用户报障原场景的自检：`summon.cmd = foldertest=<文件完整路径>`

- 报障原文是"**抽屉里点文件夹里面的文件**"——这条链路 = `OpenFolder()` 建弹窗 → 每个成员 `BindOpen(path, g)` 生成闭包 → 点图标/文字触发 `LaunchItem(path)` → `g.Destroy()`。之前的 `--launch=` 只覆盖了后半段，弹窗与绑定这一段没有机器级证据。
- 现在 `OpenFolder()` 会把每个成员真正绑上去的那个闭包存进 `global FOLDER_BINDS`（`Map("path","name","fn")`），并记 `folder: opened <名字> tiles=<n>`。自检命令 `foldertest=<某文件完整路径>` 会：找到该文件所在的文件夹 → `OpenFolder()` → 1.4 秒后**调用 FOLDER_BINDS 里那个真实闭包**，等价于用户点了一下。
- 实测（2026-11-03 21:54，抽屉 pid 13236）：
  - 文件成员 `C:\Users\25606\Desktop\Linux.txt`（文件夹「相关基础操作及密钥」，5 个成员）→ `foldertest: click tile 'Linux'` → `launch agent: status=200 16ms` → `launch via agent: …` → 记事本打开、`folder popup visible=0`（弹窗按设计自毁）。
  - 目录成员 `C:\Users\25606\Desktop\电棍小采样`（文件夹「抽象」，3 个成员）→ `launch dir: …` → 资源管理器打开、`folder popup visible=0`。这正是用户当年 `wheel.log` 里那两条 `launch dir:` 的同一条路径。
- 结论：`OpenFolder` 的闭包绑定是**逐成员正确**的（不是"全绑到最后一个"那类经典坑）；文件夹内点文件、点目录都实测打开。
- 收尾：自检完记得 `summon.cmd = hide`、关掉测试开的资源管理器/记事本窗口；`verify.ps1` 应仍 EXIT=0。

## 11. 2026-11-03 深夜～04 凌晨：三条报障 + 审计日志 + 受控重构

这一轮全部由「先取证、再改、再机器验证」驱动。三条报障的表象都很像"程序坏了"，实际根因各不相同，值得逐条记下来。

### 11.1 滚轮唤不出抽屉 —— 事件根本没进进程

**取证**（`summon.cmd=diag` 的快照）：
```
page=0 vis=0 desk=0 ... raw_ok=1 raw_alive=0 hk_alive=1 raw_ticks=960 raw_msgs=960 wheel_hits=2 last_dir=-1 last_src=hk hk_age=597719
```
- `hk_alive=1`：底层鼠标钩子活着，曾经收到过 **一次向上**滚。
- `raw_ticks=960` 但 `raw_alive=0`：Raw Input 在收消息，但 **960 条全是鼠标移动，没有一条滚轮**。
- `wheel_hits=2`、`hk_age≈10 分钟`：决策层只被调过 2 次，之后 10 分钟没有任何滚轮事件。
- `wheel.log` 里从来没有 wheel-down 的任何一行 —— 但当时**无法判断是"没收到"还是"收到了被 return 挡掉"**，因为 `$WheelDown` 的日志写在 `return` 之后。

**改法**（顺序很重要）：
1. 先让现象可观测：`$WheelDown/$WheelUp` **第一行无条件计数**并 60 秒限流落一行 `wheel: hk down n=…`；Raw Input 把"移动"与"滚轮"分开计数（`raw_move` / `raw_wheel`）；`diag` 增加这四个字段。
2. 再给等价入口：**屏幕热区**（`EdgeProbe`，120ms 轮询光标位置）。这条通道只读坐标，不依赖任何钩子，蓝牙鼠标/触摸板/驱动拦截都绕得过去。
3. 顺手修 `WheelPassThrough` 里用 `WinGetClass("ahk_id h")` 的写法 —— 它撞上 `WorkerW` 会抛 `Target window not found`，而这个函数就在滚轮热键的调用链上，抛一次整条热键体就断。改用 DllCall 版 `WinClassOf/WinProcNameOf/WinTitleOf`。

**热区的位置不能想当然**（踩了两轮）：
- 第一版把热区放在屏幕物理底边 → 但那正好压在任务栏上，`ClassifyDeskWindow` 判"非桌面"，永不触发；若为它放行任务栏类，又会跟开始菜单抢点击。
- 第二版用 `SPI_GETWORKAREA` 算"任务栏上沿" → 本机**任务栏是自动隐藏**，工作区=整屏，算出来还是 1440，白算。
- 第三版：`FindWindowW("Shell_TrayWnd")` + `GetWindowRect` 读任务栏真实高度（本机 72px@150%），热区 = **任务栏上沿往上 8px 起、40px 厚**，两种任务栏模式都落在壁纸上。参数从 `edge: probe init … taskbar=72 zone=1320..1360` 这行日志可核对。

**仍然没解决的部分**：本机滚轮只有"向上"能进进程（`hk_up` 涨、`hk_down` 恒 0）。这是蓝牙 HID/驱动层现象，AHK 侧无法修，所以留底缘热区当主入口，并把诊断三字段写进文档。

### 11.2 文件夹打不开 —— 两次错误假设

**取证**：`wheel.log` 有 `launch dir: C:\…\计算机辅修`，说明点击到达、`Run('explorer.exe …')` 也被调用了；而软件类走代理 `launch agent: status=200 0ms` 秒开。差异只在"谁去调 explorer"。

- **假设一：explorer 单实例转发把路径塞进了后台旧窗口** → 于是改用 COM `Shell.Application.Explore()`（强制新窗口）。
  **实测失败**：`dirtest` 只留下 `launch: enter [...]` 一行，之后既无日志也无异常，**线程却没卡**（同进程的 `diag` 仍能响应）。也就是 `ComObject("Shell.Application")` 在本机 AHK 里既不返回也不抛 -> 不可用，已弃用（`项目地图` §8-8）。
- **假设二：AHK 当祖先导致外壳行为异常**（这是项目里反复出现的模式）→ 目录也**交给代理**（代理进程没有 AHK 祖先，且 `/launchpath.gif` 已验证 45~63ms）。
  **实测通过**：`dirtest` → `launch dir ok via agent … (31ms)` → 资源管理器出现 `3123003386谭熊煊 - 文件资源管理器` 新窗口（用 `Get-Process explorer | Select MainWindowTitle` 前后对照验证）。

**最终形态**：目录 = 代理优先 → `Run` 兜底 → 全失败弹气泡；日志统一 `launch dir ok via agent|run` + 耗时。虚拟文件夹弹窗则修了 z 序（打开时 `HideOverlay()`、`SetWindowPos(TOPMOST)`、关闭后 `RestoreOverlayForDrawer()`）。

### 11.3 控制台"连接失败" + ▲▼ 失效 —— 单线程被慢探针拖住

**取证**：`dsh-agent.log` 里 `/state.js` 反复 **800–1375ms**，而页面看门狗只有 2500ms；代理是单线程，慢一次就排队。

**根因拆开是两笔账**：`Test-WebUp` 在 DSH web 没起来时要挨个试 6 个端口（关闭的端口每个 120ms+，合计 ~760ms），再叠加 `Get-Balance` 失败时每次请求都重试（224ms）。

**改法**：给 `/state.js` 的五个字段各自设 TTL（`lines` 500ms / `web` 3s / `busy` 1s / `drawer` 2s / `bal` 300s），余额失败加 30 秒负缓存；`/media.js` 1s 缓存并在播放动作后主动失效。实测 **10–34ms**。
页面侧配套：看门狗 2500→4000ms、**连续 3 次失败才判离线**（前两次只显示"重试中"且不清空内容）、▲▼ 改 `scrollBy` 且"日志不足一屏"时置灰并给 title。

> 教训：单线程 HttpListener 里，"探测开销"必须变成"带 TTL 的缓存值"，否则探针越勤、系统越慢、页面越容易判死，形成正反馈。

### 11.4 统一审计日志（新组件）

- **一个文件** `audit.log`，三方共写，靠行首标签区分：`[AHK ]` / `[API ]` / `[WEB ]`；行格式 `yyyy-MM-dd HH:mm:ss.fff [TAG ] action key=value`。

- **页面怎么写日志**：壁纸是 `file://`，不能 fetch → `audit.js` 用 1×1 GIF 信标打 `/audit.gif?e=&k=`，同类事件 500ms 节流。

- **轮转** 2MB → `audit.log.1`；导出靠 `summon.cmd` 写 `log=200` 生成 `audit-export.txt`（用户不用敲命令）。

### 11.6 这一轮新增的三个调试陷阱

1. **用 `Start-Process` 起抽屉，进程会随发起它的会话/作业对象退出而被回收**。现象：手工重启后"过一会儿抽屉自己没了"，日志停在 `screen:` 那行、无 ERROR、无 `exit cleanup`，看着像崩溃。→ 一律用 `Start-ScheduledTask '\DesktopPage Autostart'` 重启。
2. **`SetTimer(() => Foo(localVar), …)` 这个坑又踩了一次**：`dirtest` 第一版写成箭头函数捕获 `dp`，1.2 秒后局部变量已失效 → 只剩 `dirtest: begin` 一行。→ 必须 `SetTimer(DirSelfTest.Bind(dp), -1200)` 按值捕获（§9.7 早写过，这次是复现）。
3. **测试用例"扫全文件"会把历史脏数据算成新问题**：`SEC-003` 修好后用例仍红，因为 `audit.log` 里还留着修复前的注入样本。→ 处理方式是**归档日志**（`audit.log.bak-<时间>`）而不是删，既保住证据又让断言只看现在。

### 11.7 滚轮"打包后失效"的回溯（11-04 上午）

**回溯方法（值得复用）**：`E:\DSHWORK\_archive\2026-11-03\rollback-1101\` 存着**打包前（11-01）**的 `_backup-DesktopPage.ahk`。把它和当前版本 diff，输入层只差两处：

**同时踩到一个自己造的坑，必须记住**：
某次"删空行"的编辑把 `DirSelfTest(p) {` 和它下面第一句合并成了一行 →
```

```
AHK 解析失败。**判断"AHK 脚本加载失败"的三个特征**（这次全靠这三点定位）：

**仍待人手验证**：`hk_down` 能不能开始计数（去掉了周期性重装之后）。若仍为 0，就是蓝牙鼠标驱动层的问题，靠 `wheel.js` + 底缘热区兜底。

### 11.8 滚轮的最终结论：事件在系统层就不存在（11-04 晚）

连续排除了四层，才敢下这个结论：

| 层 | 观测方式 | 结果 |
|---|---|---|
| AHK 低层钩子 | `$WheelDown`/`$WheelUp` 首行计数，`diag` 里 `hk_down`/`hk_up` | **恒 0**（自 11-03 22:41 起只见过 1 次向上） |
| AHK Raw Input | `RIDEV_INPUTSINK` + 报文分类计数 | 收到 **1052 条移动、0 条滚轮**（竖向横向都没有） |
| 壁纸页面 | `wheel.js` 加载时打 `wheel.ready`，`wheel` 事件打 `wheel.any` | 有 `wheel.ready`、**无 `wheel.any`** → 页面收不到滚轮 |
| 关掉 Lively 做 A/B | 停 `Lively.exe` 后再滚 | 仍然全 0 → **与 Lively 的输入转发无关** |

> 顺带纠正一个 11.7 里的推测：当时判断"打包后加的周期性 `InstallMouseHook` 导致收不到"，但去掉它之后 `hk_down` 依然是 0 —— 那条改动保留（少一层无用的强制摘挂没坏处），但**它不是根因**。

### 11.10 真根因与修复：不是"事件不存在"，是"到不了 AHK 进程"（11-05 00:05）

> 11.8/11.9 的结论「报文在到达入口之前就被上层翻译/注入了，代码层面无解」**是错的**。错在对照取样：那次 `diag` 全 0 是真的，但同一时刻我并没有另一个进程在做参照，于是把"AHK 收不到"当成了"没人收得到"。

这次的决定性对照（同一时刻、同一桌面、同一个鼠标）：

| 观测者 | 通道 | 结果 |
|---|---|---|
| C# 监听器（PowerShell `Add-Type` 托管，隐藏窗口 + `WH_MOUSE_LL` + Raw Input） | 底层钩子 / Raw Input | `RAW WM_INPUT wheel #n delta=-120`、`LLHOOK WM_MOUSEWHEEL #n data=-120`；`beat raw=1051 rawwheel=86 hook=1115 hookwheel=86` |
| AHK 探针（`~WheelDown` + `RIDEV_INPUTSINK` 双目标） | 钩子 / Raw Input | `beat msg=0 wheel=0 hk=0` 一路到底 |
| AHK 抽屉本体 | `diag` 的 `hk_down/raw_ticks` | 一动不动（22:32 收过 576 次，23:07:50 之后归零） |
| `A_TimeIdleMouse` 探针 | AHK 输入空闲时间 | 单调增长（期间光标在动），而 `idle_kbd` 反复刷新 → **键盘钩子活着，鼠标钩子/raw 全聋** |

结论：**滚轮事件在系统层完全正常（`delta=-120` 就是向下滚），只是进不了 AutoHotkey 进程**。同一天里它是"间歇性整体哑掉"——22:32 能收 576 次、23:07 之后一次都没有，所以历史上"有时能用有时不能用"的直觉是对的。

修复：新增 `drawer\wheel-bridge.ps1`（**PowerShell 必须作为宿主**，见下），把滚轮投递给抽屉。

| 尝试 | 结果 |
|---|---|
| 同一份 C# 代码编成 exe，经 `explorer.exe` / `cmd /c start "" /b` / `Start-Process` 启动 | `hits=0`，一条都收不到（三次都复现） |
| 同一份 C# 代码放进 `powershell.exe` 托管（`Add-Type` + `Main()`） | 立刻收到（注入 3 次即 `hits=3`，物理滚动即 `posts` 增长） |
| `PeekMessage` + `Thread.Sleep(40)` 轮询版 | `hits` 恒 0 —— 底层钩子回调必须由**阻塞式 `GetMessageW`** 的消息循环接收，轮询也不行 |
| 自写 `SetWindowsHookEx` 到 AHK 里 | 回调从不触发（`hm=0`），AHK 只能用原生热键 |

桥的行为（详见 `项目地图.md` §4.1）：只认 `WM_MOUSEWHEEL`、**丢弃 `LLMHF_INJECTED`**（否则抽屉自己 `Send("{WheelDown}")` 透传会被当召唤信号形成回环）、`PostMessage(抽屉, 0x8001, 1=下 / 2=上)`、句柄从 `wheel-bridge.hwnd` 每 2 秒重读、每 55 秒心跳、180 秒无回调且系统最近有输入则摘钩重装、单实例互斥体、日志 256KB 两代轮转。

抽屉侧 `WheelBridgeMsg` 复用原有 `WheelHandle(dir, "bridge")`，与 `$WheelDown`/`$WheelUp` 共用 120ms 去重；`curPage=0` 时只处理"向下 + 光标在桌面"，其它位置直接 return（不抢应用的原生滚动）。

实测（用户物理手滚）：桥 `hits=679 posts=50`，抽屉 `wheel-down drawer=1 via bridge` → `ShowDrawer vis=1` → `overlay shown`；向上滚 `HideDrawer vis=1`。

**仍未完全解释的一点**：为什么 AHK 进程会整体收不到鼠标事件、而 PowerShell 进程能收到。当前是"绕开"而不是"修好" AHK（第三方运行时，本机无法重编）。若以后 AHK 上游解决，桥可以直接撤掉，`$WheelDown` 热键双通道会照旧工作。

## 12. 2026-11-05 修复：资源管理器里滚轮下滑误召唤抽屉

### 12.1 现象与根因

- 报障：在**文件资源管理器**窗口里把滚轮向下滚，抽屉会滑出来（在桌面上滚是正常的，这正是设计行为）。
- 现场证据（`wheel.log` 11-05 09:04）：`hover: desk=1 cls=SHELLDLL_DefView proc=explorer.exe at=149,235` —— 光标下命中的是 `SHELLDLL_DefView`，`proc=explorer.exe`，判定层给了 `desk=1`。§9.5 里那条一模一样的记录，当时被当成了"壁纸判定正确"的样例，其实同一个位置就是本 bug。
- 根因：`ClassifyDeskWindow()` 原本沿光标命中的**内层**窗口往上 8 层父链看类名，白名单是 `Progman / WorkerW / SysListView32 / SHELLDLL_DefView / SysHeader32`。桌面的图标层确实是 `Progman → SHELLDLL_DefView → SysListView32 → SysHeader32`，但 **Windows 11 资源管理器（`CabinetWClass`）的文件列表区也挂 `SHELLDLL_DefView`**：

  ```
  CabinetWClass
    ├─ TITLE_BAR_SCAFFOLDING_WINDOW_CLASS / InputNonClientPointerSource
    └─ ShellTabWindowClass
         └─ DUIViewWndClassName → DirectUIHWND → CtrlNotifySink
              ├─ SHELLDLL_DefView            ← 文件列表区（与桌面图标层同名）
              │    ├─ FileExplorer_FolderViewIsland
              │    └─ DirectUIHWND → CtrlNotifySink → ScrollBar
              └─ NamespaceTreeControl → Static / SysTreeView32   ← 左侧导航栏
  ```

  于是"内层类名命中即算桌面"这条判据泄漏到了所有带同名子窗口的进程上：判 1 → `DesktopUnderCursor()` 为真 → 滚轮下滑直接 `ShowDrawer()`。
- 实测现象以外的旁证：同一台机器上资源管理器里滚**上**滑不收起抽屉（上滑只看 `curPage`），只有下滑召唤，与报障一致。

### 12.2 改法：判定只认顶层窗口（`drawer\DesktopPage.ahk` 的 `ClassifyDeskWindow`）

```ahk
root := DllCall("GetAncestor", "Ptr", h, "UInt", 2, "Ptr")   ; GA_ROOT
```

### 12.4 顺带修掉的两个启动链问题（同一个部署窗口里暴露的）

1. **`start-all.vbs` 永久挂死**（真 bug，11-04 23:53 接入滚轮桥时引入）：文件头有 `Option Explicit`，而 4b 段落新增的 `bridge = appDir & "\wheel-bridge.ps1"` 没写进 `Dim` 行 → 每次执行到那里就抛「变量未定义」，wscript 弹一个**不可见的模态错误框**永久挂住。后果：计划任务 `DesktopPage Autostart` 卡在 Running（`LastTaskResult=2147946720` = `0x800710E0` 请求被拒，`MultipleInstances=IgnoreNew` 之后再也启动不了），后面的 hwmon / wxmon / 代理 / 看门狗 / dock-add-host 全部不再被拉起。修法：`Dim …, cand, list, bridge`。实测修复后一轮日志完整：`start → lively: already running → drawer: already running → agent: already up → done`，任务状态回到 Ready。
2. **`drawer: STILL DOWN after start` 误报**：抽屉冷启动实测 4~6 秒（114 个图标要抓图标 + 算布局），而启动脚本 `WScript.Sleep 3000` 死等 3 秒就判死，导致每次正常重启都往 `start-all.log` 留一行 STILL DOWN，`verify.ps1` 取末尾 12 行 → 直接 FAIL（退出码 1）。改成 `For i = 1 To 15: If DrawerAlive() Then Exit For: WScript.Sleep 1000: Next`（每秒探测、最多 15 秒）。
3. **重启抽屉后必须重启桥**：桥把抽屉 hwnd 缓存成目标（从 `wheel-bridge.hwnd` 读），抽屉换实例后桥仍往旧 hwnd 投（`post FAILED dir=1 via=hook target=3607870`），而桥有单实例互斥体 → 新桥启动即 `another instance running, exit`。正确顺序：kill 旧桥 → 跑一次 `start-all.vbs`（或 `schtasks /run /tn "DesktopPage Autostart"`）→ 日志出现 `target: drawer hwnd=4195588` 才算恢复。这条加进重启铁律。
