`git log -S` 确认这段从首发提交 `e92c2bb` 就存在。上一轮看的大概是 `E:\DSHWORK\pkg\大肥鱼桌面系统`（切到 git 仓库前的那份打包副本）。

> 教训：挂账前先确认自己读的是不是**当前生效的那份**。这份文档 §9 已经记过「源工程切到 dev 分支」，

**2. `scroll.dat` 没有上限（新发现，真缺陷）**

| 环节 | 原来 | 风险 |
|---|---|---|
| `Invoke-ScrollGif`（代理写） | 无条件 `AppendAllText` | 消费方一停就只增不减 |
| `AgentScroll()`（AHK 写） | 无条件 `FileAppend` | 同上 |
| `Take-Scroll`（代理读，每 80ms） | `ReadAllText` **整份**读 | 文件越大每次越慢，单线程主循环被拖住 |

消费方是谁：壁纸页 `dsh.js` 的 `scrollPoll()`。它一停（Lively 没起、壁纸页脚本报错、`index.html` 被换），
`scroll.dat` 就只进不出。这条正好踩在铁律 §7.1-3 上：**单线程代理里任何 >200ms 的同步操作会连坐所有接口**。

**3. `verify.ps1` 的输出一直是团乱麻**

`Invoke-WebRequest` 默认画进度条，把 `[ OK ]` 一行行冲掉。实测输出长这样：

```
[ OK ] GET /state.js -> ... 正在读取 Web 响应 正在读取响应流... (读取的字节数: 0)
[ OK ] DesktopPage.ahk 存在   [ OK ] dsh-agent.ps1 存在   ...
```

上面那些「`DesktopPage.ahk 存在`」根本不是这一次打印的，是上一屏被进度条覆盖后的残影。
**自检的输出是给人看的**，被切碎之后「全部通过」这四个字都要在乱码里找。

**4. 一次对照实验顺手证明了测试方法本身有分辨力**

`SEC-008` 改成隔离实例后，必须回答一个问题：**它凭什么算通过？会不会不管代码怎样都绿？**
做法是跑对照组——同一份代理，只把清洗那一行删掉，其余一模一样：

| 变体 | 前 → 后 | 增量 | 末行 |
|---|---|---|---|
| A 真实代码 | 2 → 3 | 1 行 | `SEC008 INJECTED-BY-TEST` ✅ |
| B 对照组（删掉清洗行） | 2 → 4 | **2 行** | `INJECTED-BY-TEST` ❌ |

对照组确实红了，说明这条用例验的是行为、不是"跑过就算"。

**5. `todo.txt` / `todo-data.js` / `dock.txt` 三处不是原子写（新发现，真缺陷）**

`Save-TodoItems` 和 `Save-Dock` 都是 `[System.IO.File]::WriteAllText(目标, …)` 直写 ——
写之前文件会先被截断，写完才补齐。这个窗口通常只有几百微秒，但撞上就是：

| 谁在读 | 撞上时的表现 |
|---|---|
| 壁纸页 `<script src="todo-data.js">` | 半个对象 → **整页脚本语法错 → 待办面板空一片** |
| 抽屉读 `todo.txt` | 少几条 |
| AHK / `/dock.js` 读 `dock.txt` | 快捷启动少几项 |

项目自己的铁律（本文 §5 / `项目地图` §5）写着「数据落盘一律临时文件 + 原子替换」，
`hwmon` / `wxmon` / AHK `LayoutSave` 都照做了，唯独代理这三处漏了。

**6. `DAT-005` 是假阳性：测试自己撞了采样进程**

这条用例原来直接 `node --check <壁纸目录>\hw-data.js`，而 `hwmon` 每 2s 用
`Move-Item` 覆盖同一个文件。某一次跑出 `node:internal/process/promises:394`，
而**同一个文件手跑 120 次、再拿 400 次并发覆盖复现，全部通过**——说明是"node 打开文件的那一瞬文件正在被替换"。

两件事一起改：用例改为**先快照到临时文件再验**（快照读失败重试 5 次），报错取 node 输出的真错误行而不是内部栈首行。

## 2026-11-05　凌晨：滚轮唤出抽屉 —— 找到真根因并修掉

> 用户诉求：11-02 打包之后「鼠标滚轮向下唤出抽屉」失效，之前改过好几次没修好，要求找出原因并真正修好。
> 结论先说：**既不是代码回归，也不是鼠标/驱动/系统问题，而是"AutoHotkey 进程的鼠标输入通道会整条哑掉"**。
> 之前 §8-11 那个"滚轮事件在本机根本到不了用户态"的判断是**错的**——事件到得了用户态，只是到不了 AHK。

### 测试结果

- 命令：`powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1`
- **53 条用例：通过 50 / 失败 0 / 警告 2 / 跳过 1**，退出码 0（`SEC-004`/`SEC-005` 仍是既有的两条"需人确认"警告）。
- 中途一次失败是自己引入的：`install.ps1` / `ensure-all.ps1` / `wheel-bridge.ps1` 被写成**无 BOM** 的 UTF-8，PS 5.1 读中文直接语法错（`STA-002`/`STA-004` 转红），补回 BOM 后复绿——这条正好验证了"PS 脚本必须 UTF-8 with BOM"的规矩。

### 发现的问题（按证据顺序）

| # | 现象 | 排除/结论 |
|---|---|---|
| 1 | 抽屉 `wheel.log` 里 `wheel: hk down` 全天只有 3 条，而 `ShowDrawer` 有 53 次（全是 `^!Space`) | 抽屉的渲染层/决策层没问题：`summon.cmd=show`、`--wheel=1` 自检、`PostMessage(0x8001)` 都能唤出 |
