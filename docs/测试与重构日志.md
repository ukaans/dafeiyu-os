## 2026-11-05　凌晨：滚轮唤出抽屉 —— 找到真根因并修掉

> 用户诉求：11-02 打包之后「鼠标滚轮向下唤出抽屉」失效，之前改过好几次没修好，要求找出原因并真正修好。
> 结论先说：**既不是代码回归，也不是鼠标/驱动/系统问题，而是"AutoHotkey 进程的鼠标输入通道会整条哑掉"**。
> 之前 §8-11 那个"滚轮事件在本机根本到不了用户态"的判断是**错的**——事件到得了用户态，只是到不了 AHK。

### 测试结果

- 命令：`powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1`
- **53 条用例：通过 50 / 失败 0 / 警告 2 / 跳过 1**，退出码 0（`SEC-004`/`SEC-005` 仍是既有的两条"需人确认"警告）。
- 中途一次失败是自己引入的：`install.ps1` / `ensure-all.ps1` / `wheel-bridge.ps1` 被写成**无 BOM** 的 UTF-8，PS 5.1 读中文直接语法错（`STA-002`/`STA-004` 转红），补回 BOM 后复绿——这条正好验证了"PS 脚本必须 UTF-8 with BOM"的规矩。

### 发现的问题（按证据顺序）

| # | 现象 | 排除/结论 |
|---|---|---|
| 1 | 抽屉 `wheel.log` 里 `wheel: hk down` 全天只有 3 条，而 `ShowDrawer` 有 53 次（全是 `^!Space`) | 抽屉的渲染层/决策层没问题：`summon.cmd=show`、`--wheel=1` 自检、`PostMessage(0x8001)` 都能唤出 |
| 2 | 22:32 用户手滚，`hk_down` 一次涨到 576、`wheel_hits=951`；23:07:50 之后又归零 | **通道是"间歇性整体哑掉"，不是"永远收不到"** → 之前"本机滚轮只有向上能进进程"的经验是采样偏差 |
| 3 | 同一时刻 C# 监听器（`Add-Type` + `WH_MOUSE_LL` + Raw Input）日志：`beat raw=1051 rawwheel=86 hook=1115 hookwheel=86`、`RAW WM_INPUT wheel delta=-120`、`LLHOOK WM_MOUSEWHEEL data=-120` | **系统层完全正常**：事件确实到达用户态，且向下滚就是 `delta=-120` |
| 4 | 同期 AHK 探针（`~WheelDown`、Raw Input 挂 `A_ScriptHwnd` 与 Gui 两个目标）→ `beat msg=0 wheel=0 hk=0`；`A_TimeIdleMouse` 单调增长而 `idle_kbd` 反复刷新 | **AHK 的鼠标钩子/raw 全聋，键盘钩子活着**——不是"钩子被摘"（`LowLevelHooksTimeout=25000`）、不是 `#HotIf`/`Suspend`（全库没有） |
| 5 | 把同一份 C# 代码编成 exe：经 `explorer`、`cmd /c start /b`、`Start-Process` 三种方式启动 → 全部 `hits=0`；同一份代码放进 PowerShell 进程 → 立刻收到（注入 3 次 `hits=3 posts=0`） | **宿主选择决定成败**：桥必须由 `powershell.exe` 承载，不能编成 exe |
| 6 | 已排除的死路 | HID 直读鼠标报文（鼠标主集合 `CreateFile=ACCESS_DENIED`）；自写 `SetWindowsHookEx` 到 AHK（回调从不触发）；本会话 `SendInput` 注入（对任何进程都不可见，只能靠用户物理手滚）；C# 独立窗口泵（`CreateWindowEx` 曾 `err=1407`，后改用 `RegisterClassExW` + 正确实例句柄后可用） |

### 验证

- 编译/语法：`AutoHotkey64.exe /validate` 退出码 0；`ensure-all.ps1` 解析错误 0、跑一遍退出码 0；`start-all.vbs` 保持 UTF-16LE。
- **物理手滚（关键）**：桥 `beat hits=33 → hits=679 posts=50`；抽屉 `wheel.log`：`bridge: wheel down hits=1 page=0 at=600,450` → `ShowDrawer vis=1 [page=0 ov=0 total=328]` → `overlay shown` → `wheel-down drawer=1 via bridge`；向上滚 → `HideDrawer vis=1` → `wheel-up drawer=0 page=0 via bridge`。
- 自愈：`Stop-Process` 杀掉桥 → 跑 `ensure-all.ps1` → 新实例起来（`ensure: wheel-bridge was down, started`），心跳恢复。
- 回归：`tests\Run-Tests.ps1` 50 / 0 / 2 / 1，退出码 0。

### 遗留

- `wheel-bridge.ps1` 用的是**用户态底层钩子**，如果哪天连 PowerShell 进程也收不到（例如某个安全软件整条挂起钩子链），仍有兜底：`Ctrl+Alt+Space` 与屏幕底缘热区。
- 桥与 AHK 热键可能对同一次滚动各触发一次，靠抽屉侧 120ms 去重挡住；若以后发现"一次滚动翻两页"，先查这里。
- 根因里最怪的一点仍未完全解释：**为什么 AHK 进程会整体收不到鼠标事件、而 PowerShell 进程能收到**。当前是"绕开它"而不是"修好它"（AHK 是第三方运行时，本机无法重编）。若以后 AHK 上游修了这个问题，桥可以撤掉。
