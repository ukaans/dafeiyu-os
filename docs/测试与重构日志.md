### 发现的问题

1. **端口 17433 写死九处**：`dsh-agent.ps1` / `agent-watch.ps1` 的 `$Port`、`ensure-all.ps1` 的 `TestPort`、AHK `AGENT_BASE`、`api.js` 的 `BASE` 与另外四个 JS 的回退常量。改端口要同时改九处，漏一处就分叉。

4. **`wheel-bridge.ps1` 的 `Log()` 非原子**：`File.Copy` 到 `.1` 后截空，中途失败会留下重复内容；虽是日志，但和「改名成功才截空」的既有约定不一致。

6. **AHK `AgentScroll()` 无 64KB 上限**：代理侧写入有 `$script:SCROLL_MAX`，AHK 直写没有，只靠读取方 1MB 兜底。

**2. `scroll.dat` 没有上限（新发现，真缺陷）**

| 环节 | 原来 | 风险 |
|---|---|---|
| `Invoke-ScrollGif`（代理写） | 无条件 `AppendAllText` | 消费方一停就只增不减 |
| `AgentScroll()`（AHK 写） | 无条件 `FileAppend` | 同上 |
| `Take-Scroll`（代理读，每 80ms） | `ReadAllText` **整份**读 | 文件越大每次越慢，单线程主循环被拖住 |

消费方是谁：壁纸页 `dsh.js` 的 `scrollPoll()`。它一停（Lively 没起、壁纸页脚本报错、`index.html` 被换），
`scroll.dat` 就只进不出。这条正好踩在铁律 §7.1-3 上：**单线程代理里任何 >200ms 的同步操作会连坐所有接口**。

**3. `verify.ps1` 的输出一直是团乱麻**

**自检的输出是给人看的**，被切碎之后「全部通过」这四个字都要在乱码里找。

**4. 一次对照实验顺手证明了测试方法本身有分辨力**

|---|---|---|---|
| A 真实代码 | 2 → 3 | 1 行 | `SEC008 INJECTED-BY-TEST` ✅ |
| B 对照组（删掉清洗行） | 2 → 4 | **2 行** | `INJECTED-BY-TEST` ❌ |

**5. `todo.txt` / `todo-data.js` / `dock.txt` 三处不是原子写（新发现，真缺陷）**

`Save-TodoItems` 和 `Save-Dock` 都是 `[System.IO.File]::WriteAllText(目标, …)` 直写 ——
写之前文件会先被截断，写完才补齐。这个窗口通常只有几百微秒，但撞上就是：

| 谁在读 | 撞上时的表现 |
|---|---|
| 壁纸页 `<script src="todo-data.js">` | 半个对象 → **整页脚本语法错 → 待办面板空一片** |
| 抽屉读 `todo.txt` | 少几条 |
| AHK / `/dock.js` 读 `dock.txt` | 快捷启动少几项 |

项目自己的铁律（本文 §5 / `项目地图` §5）写着「数据落盘一律临时文件 + 原子替换」，
`hwmon` / `wxmon` / AHK `LayoutSave` 都照做了，唯独代理这三处漏了。

**6. `DAT-005` 是假阳性：测试自己撞了采样进程**

这条用例原来直接 `node --check <壁纸目录>\hw-data.js`，而 `hwmon` 每 2s 用
`Move-Item` 覆盖同一个文件。某一次跑出 `node:internal/process/promises:394`，

## 2026-11-14 第二轮：系统项顺序/折叠、点击速度、此电脑回收站打不开

**现象**（用户 m01150）：加了「此电脑/回收站」后原有图标顺序被打乱、出现重叠；点图标开软件很慢；这两个新图标点不开。

**根因**
1. `LoadItems` 把 SYS_ITEMS **前置** → items.tsv 每条下标整体 +2，按下标算的网格位跟着挪，而带 `dpos` 的条目不挪 → 顺序错位 + 与固定项重叠。
2. `ResolveOverlaps` 用「(x-GRID_X)/CELL_W 取整」当格键，dpos 坐标不在网格上时查不出重叠；且越界（DefaultSlot 排到屏幕外）不处理。
3. `LaunchItem` 对 `::{CLSID}` 直接 `Run explorer.exe`：抽屉是 **Low 完整性**，实测 `Run` 不抛异常但也不出窗口（探针 `shelltest.log`：cabinet before=3 → after=3）。高完整性 shell 下同一条命令正常。
4. 打开慢：`ProcessExist(同名进程)` 为真但窗口不可见时（微信/QQ 常驻托盘），`loop 25 × Sleep 200` **干等 5 秒**才进启动分支。

**改法**
- `LoadItems`：系统项改**追加在尾部**，既有下标一个不动。
- `ResolveOverlaps` 重写：按像素矩形判交（`OverlapsAny`），越界也算无效，`FindFreeSlot` 在屏幕内找**离原位置最近**的空格；只对用户显式摆过的条目回写 layout。
- `LaunchItem` 的 `::{CLSID}` 分支：先 `AgentLaunch`（高完整性代理代跑），失败才本地 `Run`。
- 启动等待 `loop 25 × 200ms` → `loop 6 × 150ms`（0.9s），常驻进程不再白等。
- `dsh-agent.ps1` 新增 shell 命名空间分支：`explorer.exe "<::{CLSID}>"` 由代理执行（实测 40ms 起窗口，整条 78ms 返回）。

**验证**：代理 /launchpath.gif 带 token 打开「此电脑」→ CabinetWClass 窗口出现、`launchpath shell: … (40ms)`；抽屉重启后 layout 重置（备份 `E:\DSHWORK\layout.backup-20261114.dat`）+ 位置按 `desktop_positions.tsv` 还原，截图 `drawer-10.png`；`Run-Tests.ps1` **79 通过 / 0 失败**。

**测试侧两处假失败**：`Data-Lines` 单行时返回字符串导致 `$lines[0].Trim()` 对 `[char]` 报错（DAT-001/002/003/004/006/007）→ 调用点统一 `@(Data-Lines …)`；`CON-017` 真令牌活体复现会和壁纸 40ms 轮询抢令牌 → 改成最多重试 5 次，任一次「拿到发射 + 紧接着无发射」即通过。

**遗留**：拖动/重扫后仍需目视确认没有跨列压字；`Ctrl+Alt+Space`、滚轮、顶栏按钮真机待验收。

## 2026-11-14 第三轮：连续重命名只能做一次

**现象**：重命名正常，但改完一个名字抽屉就把自己收起来，必须重新滑动唤出才能改下一个（用户 m01583）。

**根因（两条，叠加）**
1. 重命名框销毁时鼠标捕获释放，点「确定」那次 `WM_LBUTTONUP` 落到刚恢复的全屏覆盖层上；`OnOverUp` 见 `!IsObject(DRAG)` 就 `HideDrawer()` —— 每改完一个名字关一次抽屉。
2. `RestoreOverlayForDrawer()` 的 z 序与 `ShowDrawer()` 相反：它把抽屉抬在覆盖层之上。点击由覆盖层接收（抽屉只是画出来的），覆盖层被压在下面就「看得见、点不动」，即使抽屉没关，下一次右键也点不出菜单。

**改动**（`drawer/DesktopPage.ahk`）
- 新增 `global OVER_DOWN / OVER_DOWN_AT`：`OnOverDown` 记账，`OnOverUp` 只处理 3 秒内配对过的抬起；`HideDrawer()` 清账。孤立抬起不再收起抽屉。
- `RestoreOverlayForDrawer()` 改成与 `ShowDrawer` 收尾一致：`EnsureOverlay → 抬抽屉 → EnsureOverlay`。
- 顺手修掉上一版自伤回归：`FolderPopupWatch()` 里对**已销毁 Gui** 摸 `.Hwnd` 会抛 `Gui has no window`，计时器每 300ms 报错且永不收尾；改成 `isPopup` 身份判定 + `try vis := DllCall("IsWindowVisible", …)`。

**验证**
- 覆盖层 `PostMessage` 行为：孤立 `WM_LBUTTONUP` → 不再出现 `HideDrawer`；`WM_LBUTTONDOWN`+UP → 正常收起。
- `foldertest=` 走「弹窗→点绑定→BindOpen 销毁→计时器收尾」：日志仅一条 `folder: popup closed`，无 ERROR。
- 新增 `STA-014`（收尾必须把覆盖层抬回最顶、`OnOverUp` 必须有 `OVER_DOWN` 配对检查），改写了 `STA-013` 的监视器断言。
- `Run-Tests.ps1` 82 通过 / 0 失败，exit 0；`/ErrorStdOut /validate` exit 0。

**未验证**：真机连续重命名两个以上（合成鼠标事件不算验收，交给用户点）。
## 2026-11-14 第四轮：天气城市不跟 IP 变（一直显示北京）

**现象**：用户人已不在北京（本机出口 IP 解析为香港），天气面板仍显示「北京」，温度/湿度也是北京的（11.3℃）。

**根因**（`drawer/wxmon.ps1`）
- 「位置解析」写在进程启动路径里，外面还留着一句「位置只解析一次（失败就用北京兜底）」，循环里只取天气、永不重解析。
- 唯一服务是 `http://ip-api.com`（HTTPS 返回 403）。**开机那一刻网络没起来 / 挂了代理 / 服务临时失败** → 直接落到写死的 `$lat=39.911 $lon=116.395 $city='北京'`，之后 0:21 起跑了几小时都不会再问一次。
- 本机实测各服务：`ipwho.is` 232ms 返回「香港」且有中文；`ipinfo.io` 375ms 返回 `Hong Kong` + `lat,lon`；`ipapi.co` 403；`ip-api.com` 明文可用、HTTPS 403。

**改动**（`drawer/wxmon.ps1`）
- 新增 `Resolve-IpLoc`：`ipwho.is?lang=zh-CN` → `ipinfo.io/json` → `ip-api.com`（明文），逐个 `try/catch`，全失败返回 `$null`。
- 主循环按 `LOC_TTL = 1800s` 重解析；失败时 `LOC_RETRY = 300s` 后再试，并保留上次城市（绝不写回北京），日志 `loc: resolve failed, keep 香港`；城市变化记 `loc: 旧 -> 新 via src`。
- 结果缓存 `%LOCALAPPDATA%\DesktopPage\wx-loc.json`（`ts` 秒；超过 2 个周期视为过期），进程重启先 `Load-Loc`，避免每次开机都赌一次网络。
- `Get-WeatherUrl($loc)` 抽成函数，位置变了 URL 立即重建；新增 `wxmon.log`（256KB 轮转）记录定位来源与失败原因。
- 实测：`wx-data.js` 从 `city:'北京' temp:11.3` 变为 `city:'香港' temp:27.3 feels:31 hum:69 rain:100 cond:'毛毛雨' dress:'短袖 · 注意防晒' tmin 21.5 tmax 27.6`；`wx-loc.json` = `{"city":"香港","lat":22.2783168,"lon":114.1746891,"src":"ipwho.is"}`。`wallpaper/wx.js` 每 60s 用 `wx-data.js?v=Date.now()` 重灌，**不用重启 Lively**。

**测试**
- 新增 `STA-015`：禁止再写「位置只解析一次」；必须有三家兜底服务；主循环里必须有 `Resolve-IpLoc` + TTL + `Get-WeatherUrl` 重建；必须有 `wx-loc.json` / `Save-Loc` / `Load-Loc`。
- 干跑（`%TEMP%\wxtest` 隔离副本、`DSH_WALLPAPER` 指过去、mutex 改名、`-Interval 5` 跑 12s）→ `city: '香港'`；随后部署到运行时、杀旧 `wxmon`（pid 21040）重启（pid 29952），运行时 `wx-data.js` 同步变香港。

**未验证**：用户真人看到面板改字（需等 60s 轮询或手动刷新壁纸）。
